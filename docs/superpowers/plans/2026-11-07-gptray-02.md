# GPTray 0.2 Implementation Plan

> Execute inline using superpowers:executing-plans, test-driven-development and verification-before-completion.

**Goal:** One lazy ChatGPT WebView, two native window modes, explicit RAM release, reproducible Windows measurements.
**Spec:** User's GPTray 0.2 assignment (2026-11-07).
**Architecture:** Reuse label `panel` and the existing WebView2 profile. Change native window attributes without navigation. Hide keeps live state. Destroy only after explicit manual discard, or session-only opt-in to destructive hidden-idle unloading. No DOM inspection or JS injection.
**Tech stack:** Existing Tauri 2.11.5 / Wry 0.55.1, Rust std, NSIS, Windows 2022 MSVC. No new dependencies.

## Decisions and alternatives

The user explicitly authorizes autonomous implementation; no additional design approval gate is needed. Two simultaneous WebViews increase cost; recreating on every mode switch loses state. Native attribute switching is the preferred supported option. The automatic option cannot promise draft/generation safety: keep it off on every app launch, disclose loss in the menu, and limit its timer to explicitly hidden windows. Native close hides; Quit exits; Free RAM destroys without clearing profile data.

Use the task's existing isolated cloud checkout, on `feat/gptray-0.2`, based on PR #1's commit. Leave PR #1 and `ci/windows-build-test` unchanged; new Draft targets main and includes the unchanged CI commit plus the new feature changes. Retain old SHA for rollback. Graphify is unnecessary for the small codebase.
